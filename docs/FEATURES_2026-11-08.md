## Library performance and persistence

Desktop browsing/search uses SQLite queries with 100-row UI pages, server sorting, artist/album groups, favorites and full-text search. Queries return at most 500 tracks. A metadata cache holds roughly 4,096 tracks plus the current track and unsaved edits. Playback/preloading resolves track IDs natively, so uncached tracks can play. Queue identity lists remain in the session; queue metadata loads in 100-entry pages. Manual playlists preserve order and duplicate entries. Smart playlists resolve against the full catalog, with on-demand counts. Missing-file and duplicate maintenance also queries the whole catalog in bounded pages.

Interactive saves use revisioned patches for preferences, statistics, queue operations, playlists and session state. A favorite change does not serialize the catalog or queue. Patches cannot alter native file paths. Stale revisions return structured `CONFLICT` errors; failed writes retain edits and prevent close. Shuffle/restore remain explicit bulk operations. Legacy snapshot commands remain for compatibility and diagnostics; scans and backup validation still have collection-size costs.

SQLite version 3 normalizes queue, playlists and session state and adds query indexes, revision counters and an analysis cache. Existing databases receive consistent `library-v1-backup-*.sqlite3` or `library-v2-backup-*.sqlite3` recovery copies before upgrade. The JSON backup interchange remains schema version 1.

## Audio conversion and contracts

Rubato 5.0.1 replaces linear interpolation with preallocated, 256-tap windowed sinc conversion on the worker. Matching rates at normal speed bypass conversion. Seeks and output-rate/speed changes reset its state; initial filter delay and final padding are excluded from duration. The signal path reports conversion/bypass. Conversion never runs in the output callback. Speed changes still change pitch; time stretching is not implemented.

`src-tauri/src/ipc.rs` reflects registered Rust commands and core playback/catalog/analysis events into `services/generated/native.ts`. Tauri Specta/Specta are pinned to compatible release-candidate versions. New feature code and player transport use the generated SDK; older utility invocations remain compatible. Run `npm run generate:ipc` after signature changes. The ordinary native suite rejects stale bindings. Native validation still protects JSON, backups and file grants.

## OS media sessions

Souvlaki 0.9.3 supplies Windows SMTC, macOS Now Playing and Linux MPRIS. Title, artist, album, artwork, duration, playback state and position follow the audible track. Remote play/pause/toggle/next/previous/stop/seek route through the transport; Linux volume events are supported. Controls live on the main thread, updates are throttled, and global media shortcuts register only if session installation fails.

Windows compilation and the media-event bridge were exercised in the isolated desktop check. Physical headset buttons, lock-screen presentation and macOS/Linux execution still need platform acceptance. This does not add exclusive or bit-perfect output.

## Local analysis and recommendations

Setup provides explicit library/current-track analysis, cache reuse, reanalysis and cancellation. One background worker streams audio, hashes content with SHA-256 and caches versioned results guarded by modification time and fingerprint. It analyzes up to one hour per track and marks longer results as partial. Audio is not uploaded or rewritten.

Measurements include EBU R128 integrated loudness, true peak for mono/stereo and RMS energy. Unknown multichannel layouts do not receive inferred loudness measurements. Tempo uses onset autocorrelation; key uses FFT chroma/profile correlation. Both are estimates with confidence values and may remain undetermined. Short, quiet, variable-tempo or harmonically ambiguous material can produce uncertain results.

Queue suggestions explain similar tempo, compatible key, energy and loudness alongside favorites/history/artist/genre. Low-confidence tempo/key values are excluded from explanations. Suggestions enqueue only after selection.

## Evidence and limits

The [benchmark record](benchmarks/features-2026-11-08.json) uses synthetic metadata in an unoptimized Windows build. At 100,000 records: bootstrap was 114 ms / 54,871 bytes; the last title page was 130 ms; a favorite patch was 3,328 microseconds / 201 bytes / 3 row writes. The compatibility snapshot save was 2,264 ms. These storage/serialization measurements do not guarantee real disk, codec or UI performance.

Tests cover stale bindings, conflicts/rollback, queue ordering/dense insertions, native metadata authority, bounded pages, cancellation/cache invalidation, calibrated loudness/peak, sinc alias suppression, duration and seeks. A 100,000-entry frontend queue fixture verifies small favorite patches and retained in-flight edits. The native desktop check exercises paged search, analysis, transport events and close/restart persistence. See [VALIDATION.md](VALIDATION.md) for current checks and remaining release gates.
